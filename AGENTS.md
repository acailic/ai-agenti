## Project conventions

- Language: all content is Serbian — **latinica, ekavica**, warm teacher tone, technically precise. English terms in parentheses on first use (agent, tool use, RAG…). No Cyrillic in content files.
- License: content is **CC BY 4.0** (`LICENSE`, full legal code). Hard rule: do NOT copy, translate, or adapt anything from datawhalechina/hello-agents (CC BY-NC-SA) — only the general curriculum order is inspired by field consensus; README carries the credit note. All text/code/exercises here must be original.
- Layout: `MAPA-UCENJA.md` (11 modules 00–10, per-module outcomes/prereqs/time, ✅ status), `moduli/modul-NN-<slug>.md` (all 11 written, incl. module 10 guided final project: six parts with checkpoints, delivery requirements, self-assessment rubric, `10a_provera_isporuke.py` offline delivery gate), `REČNIK.md` (107-term Serbian–English glossary in 8 sections, linked from README/MAPA/module 00), `radionice/radionica-NN-<slug>.md` (all six 01–06 complete with worked solutions), `radionica/` (commercial package for the paid 2h team workshop „AI agenti za dev timove": `PONUDA.md` one-page offer + `ai-agenti-za-dev-timove.md` agenda/3 exercises/facilitator notes; exercise files `v1_agent.py`/`v2_eval.py`/`v3_tim.py` are embedded in the .md with importable names — v2 imports v1 — and run fully offline on mocks; `v2_eval` deliberately fails scenario t-109 (11/12) so the A/B fix lesson works — keep that coupling when editing tickets/keywords; `v3_tim`'s `# TODO: dodati logovanje…` line and the `("TODO", …)` keyword are deliberate exercise data (the reviewer agent flags a TODO left in a patch), so repo-wide TODO/FIXME sweeps always hit ~6 source occurrences (+ rendered copies in docs/) — content, not markers to close), `O-AUTORU.md` (author bio; `[...]` placeholders must be filled before going public — same for `[...]` placeholders in `radionica/PONUDA.md`), `promocija/` (paste-ready launch posts: `KANALI.md` = channel research with verified posting rules incl. elitesecurity rule 15 banning ads and r/serbia→r/AskSerbia question routing; drafts `objava-linkedin.md`, `objava-reddit.md` (question-first, per-sub variants), `objava-kratka.md` (3-sentence forum/discord), `objava-radionica.md` (soft workshop variant, no price in public text); placeholders `[sajt kursa]` for the course site and PONUDA.md contact style — fill before publishing), `CONTRIBUTING.md` (Serbian contribution guide: language/technical rules, PR checks).
- Any API exercise must read credentials from environment variables (`Z_AI_API_KEY`, optional `Z_AI_BASE_URL`, `Z_AI_MODEL`; embeddings additionally `Z_AI_EMBED_MODEL`, default `embedding-3`) — never hardcode keys; keep `.env` out of Git. Shared code conventions in modules: z.ai GLM via OpenAI-compatible client (default base `https://api.z.ai/api/paas/v4`, model `glm-4.6`), tool use via `tools=`/`tool_calls`/`role:"tool"` messages, sandbox-restricted file tools, AST-based calculator (never `eval`), RAG pipeline = chunking (sentence split, ~900 chars, ~150 overlap) → embeddings → local vector store (`indeks.json`) → cosine k-NN → answer with mandatory `(odlomak N, izvor)` citations.
- Multi-exercise files: modules use digit-prefixed names (`06a_sema.py`, `07a_agent.py`) that the `import` statement cannot load — shared code is duplicated (module 04 pattern) or loaded via `importlib.import_module` (module 07's runner, with a comment); radionice use importable `rNN_vN_*.py` names and import across exercises (radionica 04 pattern). Module 06's protocol exercises are network-free by design (JSON-RPC-shaped dicts through an in-process `posalji` "transport"), so the mock handshake is testable without an API key; module 07's eval harness pattern = versioned `eval-skup.json` scenarios + runner with deterministic checks, pass rate, threshold as exit code, and `--diff` of two saved result files. Radionica 03 teaches the agent loop offline via a scripted `LazniModel` (SimpleNamespace responses shaped like `choices[0].message`, incl. a `tool_calls`-forever scenario that trips `max_koraka`); radionica 05 uses JSONL `eval-skup.jsonl` (one scenario per line, git-diff-friendly; differs from module 07's JSON array) with an embedded demo agent "Podrška" so the workshop runs standalone, and `regex` check values must keep diacritics (`činjenica\s*1`) to match the citation format.
- Validation before commit: link-check relative links in .md files (strip fenced/inline code first — `](...)` inside code yields false positives), scan for leaked key patterns, confirm latinica/ekavica (ijekavica + Cyrillic scan — scan every chunk as it is written: LLM output tends to leak single Cyrillic letters like а/е/о into Serbian words, and U+201C “ instead of the house closing quote; house quote style is „ (U+201E) + ASCII `"`, and inside ```python blocks avoid Serbian quotes in string literals entirely — they break compilation). Python blocks in modules/radionice should compile: extract ```python fences and `py_compile` them; the agent-loop pattern is mock-testable without network.

## Site build (docs/ = generated GitHub Pages output)

- Markdown is the source of truth; `site/build.mjs` generates the static site committed under `docs/` (GitHub Pages serves from main `/docs` at https://acailic.github.io/ai-agenti-srb/). Never hand-edit `docs/`. The build wipes `docs/` with `rmSync`, so nothing source-side may live there: `promocija/` (launch material, not rendered on the site) was once committed under `docs/` and would have vanished on the next build while failing `npm run check` — fixed 2026-10-13 by moving it to root `promocija/`; keep source out of `docs/`.
- Build: `npm ci && npm run build`; `npm run check` fails if committed `docs/` is stale — run before every push that touches any rendered content (modules, radionice, radionica/, MAPA-UCENJA.md, REČNIK.md, O-AUTORU.md, README.md); rebuild and commit `docs/` in the same change. `npm run serve` = dev server on :8093 with rebuild-on-change. Dev deps pinned in package.json (marked only; no framework; output has zero external dependencies).
- Site structure mirrors content: page per module (`/modul/NN-slug/`), per radionica (`/radionice/NN-slug/`), `/radionica/` renders PONUDA.md (sales target) with `/radionica/program/` for the detailed material, `/recnik/` (live client-side filter), `/mapa/`, `/o-autoru/`, `/pretraga/` (site-wide client-side search over generated `docs/search-index.json`, diacritic-insensitive: č/ć→c, ž→z, š→s, đ→d, query „dj"→„d").
- Link rewriting resolves .md links against the SOURCE file's directory but computes URLs from the OUTPUT page dir (`rewriteLinks(html, srcDir, outDir)`); SITE_MD maps repo .md paths → site paths, everything else becomes a `blob/main` GitHub link. marked percent-encodes non-ASCII hrefs (REČNIK.md) and drops trailing slashes on dir links — normalizeTarget decodes/handles both.
- New module/radionica = add an entry to MODULES/RADIONICE in site/build.mjs (slug must match the file name) and rebuild. SEO (titles, descriptions, og, canonical, sitemap.xml) is per-page and automatic; dark/light theme is `prefers-color-scheme` only — no toggle (lesson from offers-site).
- radionica/PONUDA.md still contains `[...]` contact placeholders — they render visibly on the site until filled; that is a launch gate, not a bug.
